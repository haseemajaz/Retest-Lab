# Retest Lab v0.6.1 — experimental research prototype

An independent, editable TradingView Pine v6 displacement-and-retest indicator and Python reference. Not Auction Retest Pro, its private code, a broker bot, a performance backtest, or a trading recommendation. Trading involves loss; use paper observation first.

## New in v0.6.1: safer comparison changes
**Clear comparison** now asks for confirmation. **Undo comparison change** reverses the most recent addition, individual removal, confirmed clear or file restore, including its scenario labels and order. Undo affects the comparison only, not the editable form; it is one step, with no redo. The next comparison change replaces the previous undo point. Cancelling a clear or a restore does not change the comparison. The undo point disappears on refresh, navigation or close, so it is not a backup: use **Save comparison file** before leaving.

62 JavaScript tests (30 geometry, 10 comparison, 12 file validation, 10 undo) and 79 Python reference/CLI tests passed on synthetic inputs. Local browser checks covered undoing addition, removal, clearing and restore, clear confirmation and cancellation, form isolation, invalid files, refresh, mobile/dark display, and no calculator network requests. These checks do not establish trading performance or execution.

## v0.6.0: save and restore a comparison file
After saving one to three examples, choose **Save comparison file** to download a versioned JSON file to your device. To restore later, choose that JSON file under **Restore a comparison file**; review the count and select **Replace comparison** or **Cancel restore**. Restore replaces all current comparison cards only after confirmation; the editable form is not replaced. CSV remains a separate export-only format and cannot be restored.

Files contain scenario labels and inputs, not broker or account data. They are read and written locally by the calculator and are not sent to a server. Snapshots still disappear on refresh unless you save a file first. Treat downloaded files as private: anyone with the file can read its contents. Only version 1 comparison JSON, at most 16 KB, with one to three unique A/B/C scenarios and valid calculator inputs is accepted. Outputs are recalculated from inputs; malformed files and invalid setups leave the current comparison intact. Future versions may change calculation rules, so results can change when reopened.

## v0.5.0: compare hypothetical examples
In the standalone calculator, calculate a valid example and choose **Save to comparison**. Save up to three snapshots; each card shows direction, entry, stop, tick size, stop distance, target prices and effective R. Change the form and calculate again before saving a different example. Remove individual cards or clear the whole comparison; labels A, B and C can be reused. Saving the same calculation twice creates two snapshots. Comparison is limited to three; remove one before adding another.

The snapshots remain in the current page's memory only; refresh, navigation or closing the page clears them. They are not stored to an account or sent to a server. Use **Download comparison CSV** before leaving to save all snapshots locally. The comparison CSV has one row per target, starts with a `scenario` column, and contains the same target fields as the individual-example CSV. It is a separate file; existing example CSV output is unchanged.

Compare price distances only when the instrument and price units are compatible. Neither a wider stop nor a higher R proves a better trade. This tool does not model size, currency conversion, costs, execution, actual losses, or performance. All inputs and examples are hypothetical.

## v0.4.1: rounding-aware target details
The standalone calculator now shows each target's distance from entry in ticks, its configured R and its **effective R after tick rounding**. Effective R is the actual target distance divided by the entry-to-stop distance, displayed to four decimal places (nearest, ties up); this display rounding can itself hide a very small difference. “Changed by rounding” is determined by exact integer comparison before display rounding. This is price geometry, not a realized return. Select long or short and choose “Try rounding example” to see how half-tick price ties affect the result. “Try example” also respects the selected direction.

The CSV retains its previous columns and appends `target_distance_ticks`, `effective_r_4dp` and `changed_by_rounding` (true/false). Update any CSV consumers for the additional columns. The calculator runs in-browser and sends no inputs to a server. It is not a market feed, position-sizing tool, execution simulator, account-risk control or trading recommendation.

At v0.4.1, 30 JavaScript tests and 79 Python synthetic reference/CLI tests passed. Local browser checks covered examples in both directions, tick rounding, CSV content, invalidation, errors and mobile/dark layouts. The unchanged Pine source is not newly validated.

## v0.4.0: standalone geometry calculator
Open [the calculator](https://haseemajaz.github.io/Retest-Lab/calculator.html) or open `calculator.html` from the ZIP in a modern browser with JavaScript enabled. It is self-contained and calculates locally; calculator inputs are not sent to a server. Choose long/short, enter an entry, stop, tick size and four R multiples, then calculate the price distance in points and ticks and four target prices. “Try example” loads made-up values; “Download example CSV” saves the current calculation. Editing an input clears the previous result. It does not fetch prices, generate signals, or place orders.

Entry and stop must be non-negative, within 0–1,000,000,000, with up to eight decimal places and exactly aligned to a positive tick. Long stop must be below entry; short stop above. R values must be strictly increasing, >0 and ≤1000, with up to eight decimals. Targets must stay non-negative, within range, distinct and on the correct side after rounding; otherwise the calculator rejects the example. Decimal arithmetic uses integer units, then rounds each target price to the nearest tick with half-tick ties toward the higher price. Configured R values may differ from rounded realized ratios. This is an independent educational calculator: it may not match Pine floating-point behavior or a broker's tick rules. It ignores size, currency conversion, spread, commissions, slippage, gaps and execution. Price distance is not an estimate or cap on cash loss.

The Pine indicator is unchanged from v0.3.0 and remains unvalidated in v0.4.0. At v0.4.0, 22 calculator unit tests and 79 Python reference/CLI tests passed on synthetic inputs. A local browser test covered example/short calculations, validation, invalidating stale results, CSV export, mobile width and no remote calculator requests. These checks do not verify performance or Pine parity.

## v0.3.1: diagnostic trace
The Pine indicator is **unchanged from v0.3.0**. A new offline CSV trace emits one row per confirmed bar: state before/after, events, cancellation reason, direction, frozen levels, modeled daily fills and observed targets. It helps organize a manual TradingView comparison, but uses the same Python reference engine, does not run Pine, cannot establish parity and is not a performance backtest.

Run from the extracted folder: `python -m reference.engine sample_trace.csv --output trace.csv` (Python 3.10+, standard library). The sample bars are synthetic. The output file is overwritten if already present; the input and config files are protected against being used as the output. Without `--output`, CSV goes to stdout. Optional JSON Config overrides: `--config settings.json` (example: `{"confirm_retest": true, "expiry": 5}`). Use the names from `reference/engine.py` and match the TradingView inputs manually; `tick` must match the instrument.

Input CSV headers required: `index,day,open,high,low,close,prior_high,prior_low,prior_atr`. `index` must be consecutive, nonnegative bar indexes. `day` is YYYY-MM-DD in the indicator's selected timezone. Supply the prior range and prior ATR as TradingView would compute them; leave all three blank only for warm-up. Optional columns: ISO `timestamp` (copied into trace), `ema`, `volume`, `prior_volume_avg`, `vwap`, `in_session`, `confirmed`. Session and confirmed default to true; a false confirmed value is rejected. Volume and averages must match the feed. Blank filter inputs fail that filter. The tool starts idle, so include enough preceding history and do not assume its initial state matches a chart that already has a setup. The tool does not calculate ATR, EMA, VWAP, sessions or market data. Compare same bars, settings, session timezone and tick size, then document any mismatch. Do not treat agreement as independent Pine validation or proof of returns.

## Indicator features (v0.3.0)
- Optional minimum breakout distance as a multiple of previous-bar ATR (default 0, preserving the earlier breakout rule).
- Optional retest-side close confirmation (default OFF). A bar must span entry and close at or above entry for longs, at or below for shorts. The model records the touched level retrospectively at bar close, not an executable fill or guaranteed price.
- Optional session VWAP direction filter (default OFF): confirmed breakout close strictly above/below TradingView's built-in `ta.vwap(hlc3)`. Missing VWAP fails the filter. This is an independent interpretation, not the creator’s implementation. Feed volume, session/anchor and timeframe affect it; especially evaluate on intraday standard candles. EMA and prior relative-volume filters remain available, also off by default. All enabled filters must pass.
- Cancel reason, last-event dashboard, optional markers/levels, and long/short-specific named alerts. JSON schema is now `retest_lab.v3` with `cancel_reason` string or null; recreate all alerts when changing source or inputs.

## Rules in brief
On a confirmed breakout bar, close strictly breaks the preceding 20-bar high/low; candle body >= 0.8 prior ATR and close lies in the outer 25% of the bar. Optional breakout distance is measured beyond the boundary in prior ATR. Entry is the tick-rounded broken boundary; stop is the breakout extreme plus a 0.1 prior-ATR buffer. Require valid tick geometry and risk between 0.25 and 3.0 prior ATR. Arm for up to 10 subsequent bars. Pending cancellation precedence: calendar-day rollover, out of session, expiry, stop breached. Otherwise entry must be spanned; optional close confirmation further restricts it. Gaps that do not span entry are not modeled fills. No target is recorded on the fill bar because OHLC cannot order events. On later bars stop wins over targets, and 0.6R/1R/1.5R/2R thresholds are recorded once. T4 ends the model. Cooldown: 5 full bars after termination; cap: 3 modeled fills/calendar day. Pending setups cancel at session/day boundaries, active setups persist. These threshold observations are not orders or P&L; gaps and partial exits are not execution simulations.
