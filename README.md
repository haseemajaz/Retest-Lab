# Retest Lab v0.3.1 — experimental research prototype

An independent, editable TradingView Pine v6 displacement-and-retest indicator and Python reference. Not Auction Retest Pro, its private code, a broker bot, a performance backtest, or a trading recommendation. Trading involves loss; use paper observation first.

## New in v0.3.1: diagnostic trace
The Pine indicator is **unchanged from v0.3.0**. A new offline CSV trace emits one row per confirmed bar: state before/after, events, cancellation reason, direction, frozen levels, modeled daily fills and observed targets. It helps organize a manual TradingView comparison, but uses the same Python reference engine, does not run Pine, cannot establish parity and is not a performance backtest.

Run from the extracted folder: `python -m reference.engine sample_trace.csv --output trace.csv` (Python 3.10+, standard library). The sample bars are synthetic. The output file is overwritten if already present; the input and config files are protected against being used as the output. Without `--output`, CSV goes to stdout. Optional JSON Config overrides: `--config settings.json` (example: `{"confirm_retest": true, "expiry": 5}`). Use the names from `reference/engine.py` and match the TradingView inputs manually; `tick` must match the instrument.

Input CSV headers required: `index,day,open,high,low,close,prior_high,prior_low,prior_atr`. `index` must be consecutive, nonnegative bar indexes. `day` is YYYY-MM-DD in the indicator's selected timezone. Supply the prior range and prior ATR as TradingView would compute them; leave all three blank only for warm-up. Optional columns: ISO `timestamp` (copied into trace), `ema`, `volume`, `prior_volume_avg`, `vwap`, `in_session`, `confirmed`. Session and confirmed default to true; a false confirmed value is rejected. Volume and averages must match the feed. Blank filter inputs fail that filter. The tool starts idle, so include enough preceding history and do not assume its initial state matches a chart that already has a setup. The tool does not calculate ATR, EMA, VWAP, sessions or market data. Compare same bars, settings, session timezone and tick size, then document any mismatch. Do not treat agreement as independent Pine validation or proof of returns.

## Indicator features (v0.3.0)
- Optional minimum breakout distance as a multiple of previous-bar ATR (default 0, preserving the earlier breakout rule).
- Optional retest-side close confirmation (default OFF). A bar must span entry and close at or above entry for longs, at or below for shorts. The model records the touched level retrospectively at bar close, not an executable fill or guaranteed price.
- Optional session VWAP direction filter (default OFF): confirmed breakout close strictly above/below TradingView's built-in `ta.vwap(hlc3)`. Missing VWAP fails the filter. This is an independent interpretation, not the creator’s implementation. Feed volume, session/anchor and timeframe affect it; especially evaluate on intraday standard candles. EMA and prior relative-volume filters remain available, also off by default. All enabled filters must pass.
- Cancel reason, last-event dashboard, optional markers/levels, and long/short-specific named alerts. JSON schema is now `retest_lab.v3` with `cancel_reason` string or null; recreate all alerts when changing source or inputs.

## Rules in brief
On a confirmed breakout bar, close strictly breaks the preceding 20-bar high/low; candle body >= 0.8 prior ATR and close lies in the outer 25% of the bar. Optional breakout distance is measured beyond the boundary in prior ATR. Entry is the tick-rounded broken boundary; stop is the breakout extreme plus a 0.1 prior-ATR buffer. Require valid tick geometry and risk between 0.25 and 3.0 prior ATR. Arm for up to 10 subsequent bars. Pending cancellation precedence: calendar-day rollover, out of session, expiry, stop breached. Otherwise entry must be spanned; optional close confirmation further restricts it. Gaps that do not span entry are not modeled fills. No target is recorded on the fill bar because OHLC cannot order events. On later bars stop wins over targets, and 0.6R/1R/1.5R/2R thresholds are recorded once. T4 ends the model. Cooldown: 5 full bars after termination; cap: 3 modeled fills/calendar day. Pending setups cancel at session/day boundaries, active setups persist. These threshold observations are not orders or P&L; gaps and partial exits are not execution simulations.

## Validation and limitations
79 Python reference and CLI tests passed on synthetic inputs. Python receives precomputed range, ATR, EMA, VWAP and volume; it neither compiles Pine nor proves parity or profitability. v0.2 compiled on AAPL 1D and advanced five replay bars; v0.3 has **not** been compiled, replayed, or alert-tested in TradingView due to the account's occupied chart slots. No cross-market evaluation, forward paper study or independently verified performance. See `VALIDATION.md`.
