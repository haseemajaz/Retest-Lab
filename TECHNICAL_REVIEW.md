# Technical review — Retest Lab v0.25.0

Initial review: 2026-11-13; updated 2026-11-17. Scope: source inspection of the Pine prototype, Python reference and trace tools, standalone calculator and its local comparison file, package structure and user-facing interface; synthetic automated tests and local browser checks. This is not a security certification, live market study, TradingView parity test or proof of profitability.

## v0.25.0 focused review: per-setup outcomes and to-scale visuals

- **Gap:** a trace was a flat list of bars, so answering "what happened to each setup" meant scanning every row by hand. The new `reference/ledger.py` groups trace rows into setups: a setup starts on an `armed_long`/`armed_short` bar and ends on the first later bar that stops, reaches target 4, or is cancelled, or stays open at the end of the trace. The engine guarantees the grouping is unambiguous — a new setup can only arm on a bar that started idle, so a setup can never arm on the same bar another one ends. Outcomes are `all_targets`, `stop`, `cancelled` (with the engine's cancel reason), or `open`; a setup that never fills is still listed. `summarize()` counts setups, fills, outcomes and ambiguous bars, and never computes a win rate.
- **Audit report:** the timeline is followed by a "Setup outcomes" section (04b) with the same per-setup table and counts, built from the same ledger code. `DEMO_AUDIT.html` was regenerated from the current report code with its synthetic-demonstration banner kept.
- **Calculator:** the ladder is no longer "ordered, not to scale". `ladder.js` gains `geometry()`, which maps each level to a 0–100 vertical position by actual price distance (0 at the highest price, 100 at the lowest, one decimal), and `calculator.html` renders it as an SVG chart beside the level table, with the same colors as the table rows. The range is always the levels themselves, so even a one-tick setup spreads across the full chart. The table is unchanged; the "not to scale" copy is updated.
- **Viewer:** the rejection breakdown now draws a bar per reason, sized by its share of rejected bars through the new pure `barWidth()` helper (whole percent, clamped 0–100, non-finite shares draw nothing). `TRACE_VIEWER.html` embeds the same tested module, and the integrity test still enforces the embedded copy matches `trace_viewer.js`.
- **Bug found by existing tests:** the ledger's index parser treated index `0` as missing (`0 or ''` is `''` in Python), so audit reports on traces starting at bar 0 failed. Fixed by distinguishing a missing value from a legitimate zero, and covered by a regression test. The same falsy-zero pattern was fixed for entry/stop/target values.
- **Validation:** new tests cover the ledger (all-targets, stop after a partial target, cancelled, open, integer index 0, missing columns, no-clobber), the audit setup-outcomes section, the to-scale geometry (long, short, one-tick), and the viewer bar widths. These are synthetic; they do not establish Pine parity, execution or profitability.

## v0.24.0 focused review: rejection reasons, scoped to idle bars and shown in the tools

- **Gap:** the v0.23.0 reason was recorded for a bar's breakout candidate regardless of engine state, so a bar could show both `modeled_fill` and `reject_reason` `warmup`. The v0.23.0 review documented that as a candidate diagnosis, but in practice it read as if the bar itself had been rejected while it filled or hit targets — and the viewer computed a per-reason breakdown it never displayed. `trace_rows()` now records a reason only when the bar started idle and no setup armed (`candidate is None and before == 'idle'`); `diagnose()` itself is unchanged, so idle-bar reasons are identical to v0.23.0. Traces from the two versions differ only on armed/active bars.
- **Viewer:** `trace_viewer.js` gains `rejectBreakdown()` (reason, count, share of rejected bars, sorted by count then name) and `filterRows()` (all / events / rejected / ambiguous). `TRACE_VIEWER.html` embeds the same tested module, shows the breakdown with visible rejected and ambiguous counts, and adds the two new filters. Its synthetic sample is regenerated from current engine output, and the integrity test enforces that the embedded sample still equals the engine output for `sample_trace.csv`.
- **Audit report:** the modelled-timeline preview gains a Reject reason column, and the Ambiguity & rejection section states the rejected-while-idle count and the most common reason (ties broken alphabetically). `DEMO_AUDIT.html` was regenerated from the current report code with its synthetic-demonstration banner kept.
- **Validation:** new tests cover the idle-only rule on the trace sample, the viewer breakdown and filters, and the audit column and rejected count. These are synthetic; they do not establish Pine parity, execution or profitability.

## v0.23.0 focused review: rejection diagnostics, parity and alerts

- **Gap:** a bar with no setup gave no reason — a silent non-event that looked like missing data. The new `diagnose()` in `reference/engine.py` evaluates the same conditions as `detect()` step by step and returns the first failing check in a documented order (geometry before filters, so a bar that never breaks out reports `no_breakout` even if a filter would also fail). `detect()` is now a thin wrapper over `diagnose()`, so the two cannot drift apart. The trace adds a trailing `reject_reason` column; warmup bars report `warmup`.
- **What the reason is not:** it is the first failing check, not the only one. Fixing the named check may reveal the next. In v0.23.0 it was recorded for a bar's breakout candidate regardless of engine state, so a warmup reason could appear on an armed/active bar whose prior values were blank. Changed in v0.24.0: a reason is recorded only on bars that started idle and did not arm.
- **Parity checker:** `reference/parity.py` parses Pine `input.*` defaults (stripping the Pine type prefix) and compares the 16 shared fields plus the four target inputs with the Python config. Pine-only inputs (lookback, ATR/EMA/volume lengths, session, timezone, display) are listed, not compared. Tick is not a Pine input — it is `syminfo.mintick` — so the checker notes it must be matched manually. A settings match is not chart parity.
- **Alert checker:** `reference/alerts.py` validates a v3 JSON payload's shape: schema, symbol/timeframe, bar_close_ms, direction, known non-duplicate events, cancel_reason consistency, and finite price fields. It cannot confirm an alert fired on a real chart.
- **Audit summary:** the report now counts ambiguous bars apart from clean event bars, lists ambiguity labels and rejection-reason counts, and explicitly excludes flagged bars from any win/loss-like count. The viewer counts rejections by reason; the comparator and capture worksheet accept `reject_reason`. Old 17-column traces are rejected by the viewer — regenerate them with the current engine.
- **Validation:** 32 new Python tests cover diagnose (every reason, both directions, filter precedence, risk/targets), the trace column and both new samples, parity defaults/drift/CLI, and alert shape (valid, wrong schema, unknown event, cancel consistency, bad direction/prices). One audit test checks the summary section and reject counts. Viewer tests add reject counting and old-header rejection. These are synthetic; they do not establish Pine parity, execution or profitability.

## v0.22.0 focused review: intrabar order

- **Gap:** a bar's high and low can reach several relevant levels without revealing their order. The trace previously recorded a single outcome (stop-first, or no target on a fill bar) with nothing to mark that the outcome was a convention. The new `order_ambiguity` column, computed in `Engine.step` from the setup in force before the bar and the set of targets already hit, labels exactly those bars: `fill_vs_stop`, `fill_vs_target`, `stop_vs_target`, `target_order`.
- **What is not flagged, and why:** a clean bar spanning only one deciding level is not flagged. Day, session and expiry cancellations take precedence over price in the model, so a bar cancelled for those reasons is not labelled as a price-order case even if it also spanned entry and stop. The re-arm on a termination bar uses a new setup and does not inherit the old bar's label; the label resets on every bar, including unconfirmed bars.
- **Boundary — fill vs stop on the fill bar:** in the current model a fill can only happen when the stop was not touched on that bar (the armed branch cancels first), so `fill_vs_stop` is produced by the armed-cancel path, not by a fill that also stops. The pure helper still labels that combination if called directly, but the engine never emits it from a fill. `fill_vs_target` is the reachable fill-bar label.
- **Downstream handling:** the trace CSV gains one trailing column. The viewer, audit report and comparator accept it; the viewer counts ambiguous bars, the audit shows the label per event row and a total count, and the comparator compares it as text. Old 16-column traces are rejected by the viewer (exact-header check) — regenerate them with the current engine. The capture worksheet can plan/record the field. No event, level, stop-first or fill-bar rule changed.
- **Validation:** 25 new Python tests cover the pure helper (long/short, single vs multiple targets, already-hit targets, no-setup and invalid direction), the engine (armed cancel, clean fill, fill-bar target, active stop vs target, day-rollover exclusion, label reset, no re-arm inheritance), the trace column and both synthetic samples, plus comparator acceptance. One audit test checks the report column and count. The viewer tests add ambiguity counting and old-header rejection. These are synthetic; they do not establish Pine parity, execution or profitability.

## v0.21.0 focused review: interval assumptions

- **Gap:** consecutive bar indexes alone do not show whether timestamps are spaced as expected. The optional preflight compares adjacent explicit-offset timestamps as instants with a user-specified fixed duration, using exact `timedelta` comparison including fractional seconds. Short and long positive intervals generate warnings at the later index; equal and backward instants remain separate existing warnings.
- **Unknown is not a pass:** a pair involving a blank or naive timestamp is reported unchecked; with one bar, cadence is not assessed. The tool does not bridge unknown pairs to claim a duration or guess a timezone. Existing separate ordering warnings can compare known instants across such gaps.
- **Model boundary:** no session calendar, expected bar count, trading halt, provenance, timeframe semantics, open/close convention or variable-duration schedule is checked. Long and short durations are not automatically errors. `--expected-seconds` is off by default, accepts integers from 1 through 31,536,000, and never corrects inputs. An advisory can coexist with exit 0 unless strict mode is used; audit also returns 1 for differences or missing observations.
- **Validation:** synthetic unit and CLI cases cover exact, fractional, short, long, offsets including an offset transition, missing and naive values, duplicate/reverse timestamps, single bars, strict status and unchanged data. The visual guide and requested/default report states were inspected at desktop and mobile widths. These do not verify Pine behavior or real-world trading.

## v0.20.0 focused review: coherent observation export

- **Data integrity gap:** the prior two CSV downloads represented separate moments and could diverge if the worksheet was edited between them. The new version validates one in-memory snapshot and serializes both CSV strings into one versioned array-only JSON bundle. The two independent CSV buttons remain available, with the same caveat.
- **Audit boundary:** `--bundle` is exclusive with separate observation/checklist inputs. The audit snapshots and hashes bundle bytes, decodes bounded UTF-8 JSON, checks the version and embedded CSV formats, indexes and uniqueness, and rejects observed cells absent from the checklist. An unrecorded planned cell is reported missing; a recorded blank remains present. Bundles can be forged or edited; these checks cannot establish source, observation accuracy, completeness or equivalence with a chart.
- **Privacy and consistency:** no data is auto-saved or encrypted. Unchecked draft text remains in editable backups but is excluded from bundles. Bundles are not backups. The audit reads bars and bundle separately, creates temporary copies and may leave them after abrupt termination; report and input files may be sensitive. SHA-256 identifies the bytes, not their origin or software authenticity.
- **Evidence:** synthetic tests cover the export, Python integration, malformed formats, duplicates, omissions, mismatches, out-of-plan observations, output protection and hashes. Browser checks cover desktop and mobile tested flows, not cross-browser/accessibility certification. No Pine behavior or trading performance has been validated.

## v0.19.0 focused review: half-tick decisions

- **Decision risk:** the reference's `floor(price / tick + 0.5 + 1e-10)` applies a fixed tolerance in tick units. Near a half tick, this tolerance and floating conversion or division can shift a decision from exact decimal nearest-tick rounding, including for negative prices. The inspector makes the two index decisions visible; it does not change the reference's behavior.
- **Scope:** exact arithmetic is on the decimal strings typed into this tool, with ties toward the higher price. The other result emulates only the tick-index expression using JavaScript double precision. It does not reproduce prior model operations, Python's later multiplication and 10-decimal price rounding, or Pine. Agreement is not proof of accuracy or parity.
- **Bounds:** at most 12 whole digits, 16 fractional digits for price and 10 for tick, positive tick, and absolute price/tick no more than 2^40. Inputs longer than 64 characters are rejected rather than truncated. These are inspector limits, not model limits.
- **Checks:** JavaScript cases and independently calculated Python Decimal and float-step cases include signed half boundaries; selected local desktop and mobile browser checks exercise valid, invalid and stale results. This is synthetic evidence, not chart, market or execution validation. See `VALIDATION.md` for exact counts.

## v0.18.0 focused review

- **Finite inputs are not enough:** finite OHLC, prepared indicators and configuration values can overflow when combined. Checked intermediate calculations in Python detection and rounding now raise a descriptive error if infinity or NaN is produced. Checks cover the operations actually evaluated: bar/body and breakout distances, volume/body/break thresholds, wick ratios, tick units, stop, risk and target arithmetic. Short-circuited branches and skipped detection are not assessed.
- **Fail-safe CLI:** trace, preflight and audit share this reference path and report the CSV row. When a checked error is encountered they return exit 2; trace and audit do not create a successful output. An existing trace destination remains unchanged even with `--force` because analysis precedes writing. The safeguard does not repair data.
- **Boundaries:** binary floating-point remains. Finite results can suffer underflow, absorption, rounding error or other precision loss; this check is not a numerical proof or Pine equivalence test. Preflight's conversion and tick-count warnings remain partial.
- **Regression evidence:** 247 Python and 143 JavaScript synthetic tests passed; a local seeded comparison of 5,000 ordinary-range detection cases matched v0.17. The new focused field note was inspected in local Chromium at desktop/light and 390px/dark. These are not independent Pine, market or execution tests.

## v0.17.0 focused review

- **Loss prevention:** the observation worksheet can explicitly export and restore a local JSON draft, including empty indexes, duplicates and text retained in unchecked rows. There is no background storage, merge, undo, encryption or automatic backup. Confirming restore replaces the current worksheet. A change during asynchronous file reading cancels that restore.
- **Input boundary:** the 4 MiB import limit applies before decoding; UTF-8 decoding is strict. Version, root and row shapes, fields, booleans, string limits and row count are checked before replacement. The array-only format avoids duplicate object-key ambiguity. Validation does not establish authenticity, provenance or truth. Restore permits incomplete and duplicate plans; CSV export independently rejects them.
- **Privacy:** backups contain all draft text, including unchecked entries; filenames may be renamed by the browser. Keep backups private. Separate CSVs are snapshots taken at separate times and should be exported without intervening changes. Spreadsheet formula risks remain.
- **Verification:** 232 Python and 143 JavaScript tests passed on synthetic data; selected Chromium desktop/mobile checks covered malformed and cancelled restores, replacement and a simulated read/edit race. This is not a security certification, cross-browser proof, Pine validation or performance evidence.

## v0.16.0 focused review

- **Evidence capture:** a new offline worksheet separates a recorded blank from an unrecorded observation, rejects duplicate index/field pairs and generates the comparator's two CSV formats. It does not load model predictions or establish the accuracy, origin or completeness of observations. The Python integration test exercises both files against a synthetic trace.
- **Data safety:** the worksheet has no automatic persistence or import, and browser leave warnings are not guaranteed. Each download is a separate snapshot; edits between exports can produce inconsistent files. Values are preserved, not neutralized: formula-like cells may be dangerous in spreadsheet software. Users should use safe import procedures and protect downloaded files.
- **Limits:** 500 planned cells, 1,024 UTF-16 code units per value, nonnegative safe integer indexes. The tool checks structure only; the comparator validates numerical fields, trims surrounding whitespace and confirms indexes against the trace. The two files and a complete plan cannot prove Pine parity.
- **Verification:** 232 Python and 118 JavaScript tests on synthetic data. Selected local Chromium desktop and mobile checks covered exports, duplicate errors, clear confirmation and page layout; not an accessibility certification or cross-browser validation.

## v0.15.0 focused review

- **Reproducibility:** preflight, reference trace and optional observation comparison can now be assembled in one HTML report. Each file is read once into a private temporary copy and hashed; files are read sequentially, so the set is not an atomic snapshot. SHA-256 identifies bytes but not publisher, provenance, execution environment or the code executed.
- **Evidence handling:** no observations is labeled “not run”; missing planned observations and actual differences return status 1. A recorded blank is not missing. Summary details are intentionally bounded; users must use the full underlying CLI outputs for comprehensive investigation. Warnings do not prove error or accuracy.
- **File safety and privacy:** new output is created with an exclusive hard-link operation; existing destinations and symlinks are not overwritten. The destination filesystem must support hard links. Each input is capped at 8 MiB. Temporary snapshots normally clean up, but abrupt termination can leave copies. The report contains input filenames, hashes, settings and potentially sensitive observations.
- **Presentation:** self-contained HTML escapes imported values and includes no JavaScript or network resources. A clearly labeled synthetic demonstration is included. Local desktop/mobile visual review is not cross-browser or security certification.
- **Tests:** 231 Python and 98 JavaScript synthetic tests; audit tests include snapshots, fingerprints, no-clobber, symlinks, invalid/oversized input, mismatch, missing cells, strict status, escaped text, bounded details and an input changed after snapshot. The report shares the same underlying model and does not validate Pine, real fills, data provenance or profitability.

## v0.14.0 focused review

- **Float precision:** exact source decimals may lose detail on input conversion; preflight now warns when converting to float and rendering the shortest round-trip decimal changes the supplied value. It also warns at price/tick ratios of at least 2^53. These partial heuristics do not catch every representation error (including 0.1), intermediate arithmetic error, or config-conversion issue and do not establish Pine parity.
- **Trace usability:** `TRACE_VIEWER.html` displays trace bars, filterable events and source-provided levels. It checks file size, CSV quoting, expected header, row shape and indexes, but does not verify business logic, content authenticity or transitions. It displays file content as text; it does not write, upload or persist the trace. Bounded pagination avoids rendering 5,000 rows at once.
- **Counts:** armed, modeled-fill and target-event counts derive from text in an imported file, which can be fabricated or wrong. Individual target events are not trades. No P&L, win rate or executable fill is inferred.
- **Tests:** 196 Python and 98 JavaScript tests on synthetic inputs; Chromium checks of sample, invalid import preserving state, pagination, filter, text injection and clear on desktop and 390px light/dark. These checks are neither security certification nor Pine validation.

## v0.13.0 focused review

- Ignored headers now generate warnings, potentially revealing optional-column typos; intentional extras also warn. Trace behavior is unchanged.
- Known timezone-aware timestamps are compared across blank or naive gaps. This does not identify missing values, cadence or provenance.
- The opt-in OHLC grid check uses exact rational arithmetic on decimal text and the configured constant tick. Excessive decimal precision is reported unchecked. Adjusted data or variable ticks can legitimately differ; this is not a correction, market rule check or Pine parity test. Model calculations still use binary floats.
- The offline field guide explains the preparation, preflight and comparison workflow without claiming that it runs checks.
- Pine/runtime differences, provenance, execution, costs, alerts and out-of-sample performance remain unvalidated.

## Findings and actions

| Area | Finding | Action / remaining boundary |
|---|---|---|
| Input integrity | Trace CSV could silently treat some truncated trailing fields as blank; JSON duplicate keys used the last value. | Reject malformed row lengths and duplicate configuration keys. Explicitly blank CSV fields remain valid when permitted. |
| Timestamp order | Valid ISO timestamps could be repeated or backwards while index order remained consecutive. | Preflight warns for adjacent offset-aware instants that repeat or decrease. Blank or naive timestamps break the chain. Trace execution does not enforce time order; cadence, chart mapping and session correctness remain unverified. |
| Tick alignment usability | A generic alignment error did not show what could be changed. | The calculator displays adjacent lower/higher aligned values without editing the form or recommending a choice. Other constraints and market tick rules still apply. |
| Trace file safety | Earlier trace exports replaced an existing output without a prompt; an output hard-linked to an input could also overwrite evidence. | New files are created without clobbering. Existing regular output files require explicit `--force`; input/config paths, aliases and output symlinks are refused. Temporary output is written first. The no-clobber publish step uses a hard link in the destination directory and can fail on filesystems that do not support it. |
| Python validation | Some direct model constraints used `assert`, which disappears under `python -O`. | Constraints and direct OHLC validation use explicit errors. Optimized-mode and malformed CSV/encoding tests were added. |
| Reference tick precision | The Python reference rounds to ten decimal places. A finer configured tick could silently collapse values. | Config now rejects ticks that cannot be represented to ten decimal places. This does **not** make binary-float rounding equivalent to Pine at all magnitudes or boundaries. Compare matched chart examples, particularly half ticks. |
| Calculator arithmetic | Calculator calculations use integer fixed-point arithmetic, not Python's float path. | A separate Python `Decimal` oracle checked 1,200 seeded synthetic long/short examples against JavaScript targets, tick distances, effective R and rounding-change flags. Node is required for this optional cross-language test; this is not Pine parity. |
| Input provenance | Missing session/confirmation flags default to true; enabled filters can be starved of data. | The existing preflight reports these assumptions. It cannot verify feed, session, timezone, sufficient warm-up or source accuracy. |
| State and bars | The reference starts idle, requires consecutive confirmed bars and uses supplied prior values; Pine calculates indicators from chart history. | Supply matched data and sufficient history. Inspect entry, expiry, session/day reset, stop-first ties and fill-bar target omission in replay. Synthetic reference tests are not independent Pine validation. |
| Persistence and privacy | Comparison scenarios live in browser memory until explicitly saved; restore replaces the comparison only after confirmation. | Use the local JSON backup; CSV is export-only. No account sync or broker connection. Files are readable by anyone who has them. |
| Presentation and access | Prior package lacked a local visual entry point. | `START_HERE.html` and the redesigned calculator work locally without a network request in tested flows. The screenshot is historical v0.2, not evidence for v0.3. |
| Reproducibility | A ZIP cannot contain an HTML page that embeds that same final ZIP without recursive packaging. | The package includes `website.template` and `build_site.py`: rebuild the single-file site from the outer ZIP and included guide. `SHA256SUMS` checks included file integrity; it is not a digital signature. |

## What remains unverified

- The unchanged v0.3 Pine source has not been compiled, replayed, or realtime alert-tested in TradingView. The Basic chart previously had both indicator slots occupied; existing work was not removed. See `TEST_PLAN.md` for the acceptance matrix and prerequisites.
- Alert output and broker fills were not tested; alerts are notifications only. OHLC cannot resolve intrabar sequence. Fill-bar targets are deliberately omitted and stop-first treatment is a conservative convention, not observed execution. v0.22.0 flags bars where that convention decides the outcome (`order_ambiguity`); the flag does not recover the true order.
- Cross-market/timeframe forward paper observation and independently designed out-of-sample research with spreads, commissions, slippage, gaps and execution assumptions remain to be done. No win-rate, prop-firm compliance or profit claim is supported.
- Browser checks cover selected Chromium desktop/mobile, light/dark, calculator and local file workflows, not all browsers or assistive technologies. The exact HTML layouts may vary by device.

## Reproduce local checks

- `python -m unittest discover -s tests -v` (Python 3.10+). The decimal oracle test is skipped if Node is unavailable; the core Python tools otherwise use the standard library only.
- `node --test tests/*.cjs` (Node 18+).
- `python -m reference.preflight sample_trace.csv --strict` intentionally reports sample assumptions and exits 1. It uses the same Python model, not an independent verification.
- `sha256sum -c SHA256SUMS` from the extracted package on systems with that utility. Hashes identify bundled bytes, not publisher identity.
